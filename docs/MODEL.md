# 模型与实验口径

## 1. 资源与任务生命周期

终端提交的调度元数据忽略传输耗时。任务数据在分配完成后进入网络。边缘路径包含 WLAN 上传、计算、WLAN 下载；云端路径在计算前后分别增加 WAN 上传与下载。边缘服务器属于同一个资源域，内部通信忽略。

每个 VM 默认一个计算槽。任务执行时间为 `MI / MIPS`，没有任务拆分、CPU 超售、运行中迁移或正常执行抢占。配置多个槽时，MIPS 是每槽算力，VM 总容量为 `slots × MIPS`。槽满时按 FIFO 排队；CPU 利用率是测量时段内忙槽时间除以总槽时间。

报告中的任务固定 CPU 占用百分比保留作参考，第一版不参与服务时间或容量计算：

| 应用 | 边缘 CPU/% | 云端 CPU/% |
|---|---:|---:|
| 增强现实 | 20 | 2 |
| 医疗健康 | 5 | 1 |
| 重度计算 | 70 | 10 |
| 资讯娱乐 | 10 | 0.5 |

每个接入点各有独立 WLAN 上行和下行资源，云端共用 WAN 上行和下行资源。传输按完整任务数据量串行服务，不做分组级 TCP、带宽流体共享或无线信道仿真。传播时间不持有带宽，因此不同传输的传播阶段可以重叠。

绝对截止时间是 `release + max_delay`。任何阶段超时都立即取消，移出队列或释放占用，已消耗的服务时间计入资源利用率。服务完成和零时间阶段转换的事件先于同刻截止事件，保证截止时刻恰好返回的任务成功。事件时间统一保留 12 位小数。

任务 CSV 记录每个阶段的请求、开始、服务结束、阶段结束时刻以及排队/服务/传播耗时。失败阶段保留已实际消耗的部分时间。每个任务满足：

`latency = scheduler_wait + Σ(queue + service + propagation)`。

## 2. 静态与动态信息边界

静态优化器知道整个有限任务集及释放时刻，在时间 0 一次性确定所有分配。任务仅在释放时刻开始实际传输，不预占计算或网络容量。静态评价与运行测量时段均为 `[0, 最晚任务截止时间]`。

动态终端固定所属应用类别，设备应用占比为 30%/20%/20%/30%。每个终端独立生成泊松任务；不同类别间隔不同，所以实际任务比例不等于设备比例。突发流量通过分段强度生成，到达时间不会用旧强度跨越突发边界。

动态调度沿固定窗口网格运行，只处理已经到达、尚未超时的任务。按绝对截止时间、任务 ID 排序后取最多 `max_batch` 个；其余继续等待。窗口边界处先处理完成与超时，再收集到达并调度。分配一经提交便固定。

快照仅包含当前未结束任务、资源队列、在途阶段、剩余服务完成事件与截止事件。它不包含外部未来到达轨迹或历史已完成任务。候选评价创建独立回放引擎，未选入本批的待调度任务保持待调度状态，不假设未来控制器的决定。已有在途任务的后续资源竞争包含在回放中。

`Predictor` 是基础贪心及 ACO 启发值使用的快速近似：包括当前忙槽、已排队服务和正在构建的候选路径；当前在途任务尚未进入的后续阶段由精确 `Evaluator` 处理。近似不负责最终候选排名。

## 3. 统一代价函数

所有算法最小化：

`J = w_failure × P_fail + w_delay × D + w_balance × L`。

默认权重为 `0.5 / 0.3 / 0.2`，非负且和为 1。

- `P_fail`：本批任务失败比例。
- `D`：成功任务的 `latency / max_delay` 和失败任务的 1 的平均值。
- `L = 2 × std(edge_vm_average_utilization)`：边缘 VM 时段平均槽利用率的总体标准差乘 2。

三个分量均在 `[0,1]` 内，无需用实验结果的最小/最大值归一化。候选评价时段从决策时刻到本批最晚截止时间；利用率包括该时段的已有在途任务。动态局部预测代价与整个运行的总代价对应不同任务集和时段，分别导出。

负载均衡项没有单独奖励高利用率。将任务全部放到云端可能得到低边缘不均衡值，因此结果同时报告边缘/云端利用率和云端卸载比例，并提供权重敏感性实验。

## 4. 搜索与随机性

GA、ACO、SA 使用任务到 VM 的整数分配向量，共用预测最早完成策略生成的起始解。初始化评价计入预算，三个优化算法耗尽相同候选评价预算，重复候选也进行完整回放并计数。精英保留不进行重复计数。基础策略只评价最终方案一次，搜索开销自然更低。

GA 默认种群 30、三元锦标赛、单点交叉 0.8、逐基因变异 `1/n`、精英 2；ACO 每轮 20 只蚂蚁，信息素从 1 开始，α=1、β=2、挥发率 0.2，每轮最优路径沉积 `1/(1+cost)`，信息素限定在 `[1e-6,1e6]`；SA 单任务改派，排除原 VM，初温 0.1，每 20 次提案乘以 0.95，按 Metropolis 准则接受更差方案。

独立随机流由种子和稳定 SHA-256 流名称产生，不使用 Python 随机化的 `hash()`。负载生成、每种算法搜索、bootstrap 使用不同随机流。所有算法重放同一已保存任务轨迹。

仿真时钟不包含实测搜索时间，包含调度窗口等待。`search_*` 指标由真实计时器获得；并行执行会影响这些指标，因此实际耗时比较应采用单进程和一致机器负载。

## 5. 测量、统计与复现

动态生成区间为 `[0, duration)`，测量任务按产生时刻属于 `[warmup, duration)` 筛选。预热任务继续影响后续资源状态。停止生成后，所有任务继续到完成或截止。CPU 利用率按固定 `[warmup, duration]` 积分，排空阶段不增加测量时段。

`succeeded/failed` 与时延统计按测量任务队列计算；平均、P95/P99 时延仅来自成功任务，无成功任务时导出空值。`throughput_per_s` 统计固定测量时段内返回的任务，包含跨越预热边界的返回；`cohort_success_per_s` 使用测量任务最终成功数，包含排空完成。两者定义明确分开。

Bootstrap 按独立运行种子重采样，默认 10,000 次，取均值的 2.5%/97.5% 分位数。配对差值为算法 A 减算法 B，只匹配相同场景、相同种子。重复运行键或不同任务轨迹、配置、代码指纹混合会拒绝合并。成功时延没有有效值的种子在该指标中排除，并报告有效样本数。

每次运行保存解析后的 YAML、任务 JSONL 引用及校验值、代码 SHA-256、包版本、Python/平台与处理器数。完成标记保存全部结果文件与图表的校验值；续跑发现缺失、损坏或输入变化便重算。批量工具将不同场景/种子的任务轨迹先生成一次，供各策略共享。

模型独立实现，参考 EdgeCloudSim 的模块分工与毕业报告的应用参数。第一版不声称复现原报告的性能提升比例。
